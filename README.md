# Hexlygram

Сервис для публикации фотографий: регистрация, общая лента, подписки, профиль с сеткой снимков.

**Стек:** 
- Fastify 5
- Handlebars (`@fastify/view`)
- Bootstrap 5
- SQLite (встроенный модуль `node:sqlite`)

## Возможности

- **Регистрация** по имени пользователя, почте и паролю. Имя и почта проверяются на уникальность (без учёта регистра), пароль хранится в виде хеша scrypt.
- **Вход** по имени пользователя или почте, сессии хранятся в SQLite, cookie подписана, `HttpOnly`, `SameSite=Lax`.
- **Стартовая страница** описывает сервис и предлагает зарегистрироваться (авторизованных пользователей перенаправляет в ленту).
- **Лента** публикаций всех пользователей, от новых к старым, по 10 на страницу. Подписаться на автора можно прямо из ленты.
- **Профиль** (`/u/:username`): аватар, число публикаций, подписчиков и подписок, плитка 3×3 (9 фото на страницу) с пагинацией.
- **Новая публикация** (`/posts/new`): изображение JPEG / PNG / GIF / WebP до 10 МБ и описание до 1000 символов. Формат проверяется по содержимому файла, а не по расширению.
- **Страница публикации** (`/p/:id`) с удалением для автора.
- **Настройки** (`/settings`): загрузка и удаление аватара.

## Запуск

Нужен Node.js 24+.

```bash
npm install
cp .env.example .env   # настройки, в том числе доступ к S3
npm run dev            # с автоперезапуском, http://127.0.0.1:3000
npm start              # production-режим
npm test               # тесты (node:test), S3 подменяется заглушкой
npm run test:s3        # проверка на реальном бакете из .env
```

`npm start` и `npm run dev` автоматически читают `.env`, если он есть. Файл `.env` в git не попадает.

## Хранение изображений

Фотографии и аватары хранятся либо локально в `DATA_DIR/uploads` (`STORAGE=local`, по умолчанию), либо в S3-совместимом бакете (`STORAGE=s3`). Файлы получают случайные имена `<uuid>.<ext>` и сохраняются под префиксом `S3_PREFIX`.

Как изображения попадают в браузер:

- **`S3_PUBLIC_URL` не задан** - бакет может быть приватным. Страницы ссылаются на `/uploads/<имя>`, а приложение отдаёт объект из бакета с долгим кешированием и поддержкой `ETag`/`304`.
- **`S3_PUBLIC_URL` задан** (публичный бакет или CDN) - страницы ссылаются прямо на `S3_PUBLIC_URL/<префикс><имя>`, и приложение изображения не отдаёт.

При удалении поста или смене аватара старый объект удаляется из бакета. Если удалить его не получилось, запрос всё равно завершается успешно, а ошибка пишется в лог.

| Переменная             | По умолчанию | Описание                                                |
| ---------------------- | ------------ | ------------------------------------------------------- |
| `STORAGE`              | `local`      | `local` или `s3`                                        |
| `S3_ENDPOINT`          | -            | Адрес S3-совместимого хранилища                         |
| `S3_BUCKET`            | -            | Имя бакета                                              |
| `S3_ACCESS_KEY_ID`     | -            | Публичный ключ                                          |
| `S3_SECRET_ACCESS_KEY` | -            | Приватный ключ                                          |
| `S3_REGION`            | `us-east-1`  | Регион (для большинства S3-совместимых сервисов не важен) |
| `S3_FORCE_PATH_STYLE`  | `true`       | Адресация `endpoint/bucket/key`; `false` - `bucket.endpoint/key` |
| `S3_PREFIX`            | `uploads`    | Префикс ключей в бакете                                 |
| `S3_PUBLIC_URL`        | -            | Публичный URL бакета или CDN для прямых ссылок          |

При `STORAGE=s3` приложение не запустится, если не заданы endpoint, бакет или ключи.

## Конфигурация

| Переменная       | По умолчанию | Описание                                                        |
| ---------------- | ------------ | --------------------------------------------------------------- |
| `PORT`           | `3000`       | Порт HTTP-сервера                                               |
| `HOST`           | `127.0.0.1`  | Адрес для прослушивания (`0.0.0.0` - все интерфейсы)            |
| `DATA_DIR`       | `./data`     | Каталог для базы `app.db` (и для `uploads/` при `STORAGE=local`) |
| `COOKIE_SECRET`  | -            | Секрет подписи cookie; если не задан, генерируется в `DATA_DIR` |
| `SECURE_COOKIES` | `false`      | `true` - cookie только по HTTPS                                 |
| `TRUST_PROXY`    | `false`      | `true`, если приложение работает за reverse proxy               |
| `LOG_LEVEL`      | `info`       | Уровень логирования                                             |

## Структура

```
src/
  server.js          точка входа
  app.js             сборка приложения: плагины, статика, шаблоны, маршруты
  config.js          настройки из окружения
  db.js              схема SQLite
  store.js           все SQL-запросы
  plugins/session.js сессии, flash-сообщения, проверка Origin
  storage/           хранилище изображений: local.js, s3.js
  routes/            home, auth, feed, users, posts, settings, media (отдача из S3)
  lib/               пароли, изображения, multipart, пагинация, валидация, хелперы шаблонов
  views/             layouts/, partials/, pages/
public/              CSS, JS, favicon
test/                интеграционные и модульные тесты
```
